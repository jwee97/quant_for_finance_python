## What exists now

### Release 1 (numerical and model correctness)

- **RL portfolio ledger and environment** (`src/ml/rl/ledger.py`, `env.py`, `agent.py`): a quantity-and-cash ledger, one state transition for training and for playing a policy forward, an event timeline with pending orders, a corrected drawdown
  penalty, a stated differential-Sharpe convention, rejected/clipped/forced actions with reasons, mandatory eligibility liquidation and hard position/exposure limits that outrank the optional turnover budget, ruin handling, and a state schema
  version (2) so that agents trained under the old state are refused with a retrain message.
- **Rankers** (`boosting.py`): query groups and relevance recomputed after the label filter; excluded dates and reasons recorded.
- **Graph networks** (`graph.py`): absent nodes are removed from both ends of every edge at every layer (GCN degrees, GAT keys and queries, biases, residuals); the graph's cutoff, window, asset order and relationship version are recorded.
- **Output contracts** (`contracts.py`): typed output kinds, a position-rule/output-kind compatibility check that runs before training and again on re-backtest, `signal.reinterpret_outputs` as the one explicit override, validators for
  probabilities, quantiles (with the raw crossing rate), predictive distributions and pinball loss, and `report["output_contract"]`.
- **Serialization** (`models.py`): a checksummed `QFM1` envelope (legacy artifacts still load), `ModelArtifactError` for damaged files, `ModelSchemaError` for missing features.
- **Architecture manifest** (`deep/manifest.py`) with property tests; reduced variants are labelled as reduced.
- **Registry migrations and verification evidence** (`registry.py`, `verification.py`, `webapp/ml_verify.py`): additive versioned migrations, an append-only `verification_checks` table, `ml-verify` on the command line and
  `GET /api/ml/verification` / `POST /api/ml/verification/run` in the API. Only a run of the tests writes a status.

### Release 2 (causal data and training integrity)

- **Label intervals** (`intervals.py`): the label of a row starts at the close of `t + lag` and ends at the close of `t + lag + horizon`; a model fitted at the close of `D` trains on the rows whose label ended by `D` (less the embargo), counted on the real
  calendar. Per-row intervals are persisted with the dataset (`label_intervals.parquet`); the report's fold list carries `fit_cutoff`, `label_end_max` and a hash of the training rows. Purged K-fold and CPCV on the same intervals exist as research diagnostics.
- **Restricted views** (`causal.py`): every family that reads history is bound to a `CausalView` (truncated data, sealed labels); a fit view ends at the first decision of a block, a predict view at the block's last day; `predict_latest` refuses to replay.
- **Feature and dataset audit** (`audit.py`): measured dependencies of all 85 features, the dataset audit stored in `meta['audit']` and the report (label cutoffs, exclusions by reason, stale runs, closed-market marks, point-in-time quality, session policy).
  Closed-market marks are not tradable prices. Two back-fills that used later data (strategy combination by online learning, segment labels) were removed.
- **Point in time and sessions** (`pit.py`, `sessions.py`): a published series joins on when each value became public (the fundamentals engine's rule), macro inputs carry a quality (`observed`, `estimated`, `unavailable`) and claims on the weaker ones are
  marked restricted; a daily bar is final at its market's close on the real clock, a decision sees only bars that were final, and a lag that would put an entry price before the decision is refused.
- **Lineage** (`training.py`, `ensemble_models.py`, `ensembles.py`): `TrainResult.producers()` and `oos_violations()`, the ensemble's two-stage cross-fitting record, meta-labelling's settled-label and producer-fold record.
- **Overlapping labels** (`training.dependence_weights`, optional `split.sample_weighting`): concurrency, average uniqueness and weights; the report records the treatment and whether the model used the weights.
- **Inference bundle** (`bundle.py`, `model.qfb` beside each experiment's model): schema (names, order, dtype kinds), preprocessing description, cutoffs, label convention; strict drift refusal, declared versioned adapters; the forward tracker uses it and
  flags signals for dates the saved model had already seen.
- **Surfaces**: `ml-report` prints fold lineage, the dependence treatment and the dataset audit; `ml-build-dataset` prints the audit; `/api/ml/experiment` and `/api/ml/dataset/build` return it.
- **Verification registry**: 23 requirements (P0-01 to P0-22 and P0-30) with their test files and the source files each hashes; the new test files are in the `ml-base` and `replit-python` CI lists and run in the blocking `ml-correctness` lane.

### Release 3 (research controls, reproducibility and protected holdouts)

- **Study lineage** (`research_controls.py`, `registry.py` migration 2): every entry point that looks at outcomes (a run, a tuning trial, a strategy-search candidate, an ensemble, a meta-label, a re-backtest, a feature search, an evaluation) is registered as an operation of a
  study **before it runs** (`registered` -> `running` -> `done | failed | cancelled`). Failed and cancelled operations are looks; an enclosing operation adopts the experiment it starts instead of counting it twice; the default study is the universe (`u-<universe>`), not a cache key,
  so a renamed experiment, a different feature set or a changed cache key does not start a new count; a deleted experiment leaves a tombstone that `trial_count` still counts. `lineage()` reports the raw looks next to the count of operations that `count`; no estimate of
  *independent* trials is made or implied.
- **Provenance** (`provenance.py`, migration 3): content hashes of the prices, every input table (macro, fundamentals, universe), the feature panel and the label intervals, a source-tree hash, the configuration, the seed, the fold list and the output contract, combined into an
  identity. The environment and hardware are recorded but are not part of the identity; hashing is independent of the datetime unit; when no commit is available the record says so. `report["reproducibility"]`, `experiments/<id>/provenance.json` and an append-only `provenance` table
  carry it, and `compare` / `reproducible` check a repeat run against the first within the family tolerance.
- **Protected holdouts** (`frozen_eval.py`, `research_controls.py`, migration 4): `stop_after="validation"` development runs that never read the test or forward outcomes (`guard_development`); an immutable evaluation plan; a reservation by assets, dates and the hash of the outcome content (a
  renamed asset with the same outcomes is caught); a freeze; and **one** evaluation event per plan (`begin_evaluation`: single transaction, idempotency key, `in_progress`, `resume`, an explicit `allow_reuse`). Every access is written to an append-only ledger. A direct run on an
  unconsumed reservation is refused; a run after consumption records an *exposure* and its report says `exposed_exploratory`. Re-backtests, meta-labels and combinations inherit the protection of their parents (`inherit_holdout`). The legacy `finalize=true` is routed through the same
  path with a deprecation text, and `finalize` is now off by default in the API and the search.
- **Selection-test eligibility** (`selection.py`, migration 5): the deflated Sharpe ratio, the CSCV probability of backtest overfitting, White's Reality Check, Hansen's SPA and Benjamini–Yekutieli false-discovery control, each with a state (`applied`, `not_applicable`, `unsupported`,
  `insufficient`, `failed`) and a reason; a procedure that was not applied is never reported as passed. The feature screen's adjustment is Holm's. Evidence rows are append-only.
- **Null-control pipeline study** (`null_controls.py`, migration 5): the whole search pipeline is run again on placebo data (returns circularly shifted so the dependence on the features is destroyed, targets recomputed), with a frozen design hash, exact Clopper–Pearson and Wilson
  intervals for the false-promotion rate, the verdicts `sufficient` and `controlled`, resumable replications, and a plumbing-only label for small runs. `.github/workflows/ml-heavy.yml` runs it weekly with 200 replications (minimum 100) and keeps the evidence.
- **Gate evaluator** (`gates.py`, migration 6): Gate A (algorithm verified), Gate B (strategy validated) and Gate C (operationally ready) are computed from persisted evidence only. Gate A reads current `ml-verify` rows for the source hash, the provenance record, the lineage, the
  output contract, the bundle (inherited from the parent for re-backtests), a frozen-plan evaluation of an untouched holdout, the selection evidence and the null study. The evidence that later releases supply (execution realism, statistical validation, prospective operation) has a
  placeholder provider whose answer is `blocked`. Decisions are appended to `gate_decisions`, `Registry.promote` enforces them (staging needs A and B; production needs A, B and C and a recorded human approval), and a request cannot supply a trusted status.
- **Surfaces**: `GET /api/ml/lineage`, `/api/ml/holdout`, `/api/ml/promotion-status`, `/api/ml/statistical-diagnostics`, `/api/ml/null-controls`; `POST /api/ml/evaluation-plan`, `/api/ml/evaluation-plan/freeze`, `/api/ml/evaluate`, `/api/ml/selection-tests/run`,
  `/api/ml/null-controls/run`; `POST /api/ml/train` takes `mode` (`full`, the default, records an exposure, or `development`); `quant ml-lineage`, `ml-plan`, `ml-evaluate`, `ml-holdout`, `ml-promotion`, `ml-promote`, `ml-selection-tests`, `ml-null-controls`; the experiment page shows the
  holdout state, the provenance identity and the lineage count.
- **Verification registry**: 31 requirements (P0-01 to P0-30 and P1-26) with their test files and source groups; the Release 3 test files are in the `ml-base` and `replit-python` CI lists and run in the blocking `ml-correctness` lane.

### Release 4 (executable trading and reconciled accounting)

- **Two declared evaluation modes** (`execution.py`, `config.py`, `experiments.py`): `vectorized_legacy` is the *absence* of the `execution` section (so no existing configuration hash changes and every earlier experiment is read as legacy, with `recorded: false`); `realistic_cash_equity` is an explicit
  section. A realistic evaluation of a saved experiment is a **child** experiment with a new id and its parent recorded (`rebacktest` with `execution`), counted as a portfolio variation of the same study and inheriting the parent's holdout protection. The parent is untouched.
- **One driver loop over the existing components, not a third engine.** Every fill is booked in `src/ledger` (principal at the mid, spread, impact, slippage and fees as separate journal entries; dividends, splits and borrow as cash flows), instruments come from `src/instruments`, and the
  impact law is `src/engine/costs.ImpactModel`. The signal lag (`dataset.lag + backtest.extra_lag`) is applied **once**, in the adapter; a setting that would lag a second time is refused. Orders are per-asset queued target-position orders that are resized to the remaining gap.
- **Components** (`realism.py`): dated membership and delistings (`Listing`, `Membership`); corporate actions with versions (`CorporateAction`); point-in-time ADV and tradability screens; the decision/submission/fill timeline; itemised costs that reconcile (`gross less the itemised
  costs is net`, a check and not an identity); impact with calibration provenance (an uncalibrated coefficient is reported as an assumption); order states and legal transitions; borrow availability, fees and recalls; participation limits and a capacity curve; mark policies; an FX book; futures and
  crypto-derivative helpers (rolls, variation margin, margin calls, funding, fee tiers); and a capability report that names what the data and the mode can and cannot support.
- **Missing inputs never become free.** No volume means capacity is *not established* (and the report says so); no borrow record means no new short (Gate B blocks, or `shorts: refuse`); simulated data is labelled and cannot validate a strategy.
- **Artifacts and manifest**: orders, fills, the ledger journal, daily equity and costs are written with a manifest of SHA-256 hashes (`execution_manifest.json`); Gate B re-hashes them.
- **Gate B reads the evidence** (`gates.py`, policy `gates-v2`, provider `realistic_net_oos`): a vectorized result is `blocked` (it cannot pass a requirement it does not model), a realistic one needs intact artifacts, a reconciled ledger, current `ml-verify` rows for P1-01 to P1-14 and real data.
- **Surfaces**: `POST /api/ml/rebacktest` takes an `execution` section (validated; unknown settings are refused); `GET /api/ml/trading-diagnostics`; `quant ml-realistic`; the report (`ml-report`) and the HTML report print the execution mode; the research-record page shows the mode, gross and net, itemised costs,
  capacity and reconciliation.
- **Verification registry**: 45 requirements (P0-01 to P0-30, P1-01 to P1-14 and P1-26); the Release 4 test files (`test_ml_execution_ledger.py`, `_fixtures.py`, `_pipeline.py`, `_api.py`, `_cli.py`, `test_webapp_ml_execution_browser.py`) are in the `ml-base`, `replit-python` and browser CI lists.
- **Not done, said plainly**: P1-10 is `in_progress` (stale-mark expiry and halt write-downs are classified and tested, but the adapter does not apply the write-down to the ledger); P1-12 and P1-13 are `in_progress` (multi-currency accounting, futures rolls and margin, and crypto funding are verified against independent fixtures
  at the ledger level; they are **not** selectable modes of the experiment pipeline, which is a cash-equity, daily-bar evaluation). No real-market experiment has been run in the realistic mode.

### Release 5 (statistical and prospective validation)

- **A validation policy that someone has to adopt** (`policy.py`, migration 7): the platform implies no universal Sharpe, deflated-Sharpe, PBO, p-value or paper-trading threshold. A `ValidationPolicy` is a versioned declaration with a content hash; every criterion is optional and visible; `example_policy()` is labelled illustrative and is refused by the gates until a named actor has
  adopted a policy with a note (adoption is append-only; the actor is free text, there is no authentication). With no adopted policy the Gate B and Gate C statistical items are `blocked`, not guessed; diagnostics computed under another policy are `stale`.
- **One output contract for every statistic** (`inference.py`): a `StatResult` carries the hypothesis, sample identity, frequency, units, risk-free convention, estimator, dependence treatment, settings, level, seed, replications, scope, value, interval, p-value, eligibility (`applied`, `not_applicable`, `unsupported`, `insufficient`, `failed`), reason and limitations, and no number accompanies a
  procedure that was not applied. The Sharpe ratio is reported as naive, HAC (delta method with a Newey-West covariance) and stationary bootstrap around one point estimate; a forecast horizon `h` forces at least `h - 1` lags; a bootstrap with fewer than 200 usable replications is `insufficient`; a paired difference resamples the same blocks in both series.
- **Matched benchmarks, predeclared regimes, calibration** (`benchmarks.py`, `regime_eval.py`, `calibration.py`): beta-, net-exposure-, sector- and risk-matched comparators built from information known the day before, with the unmatched equal-weight universe kept as a labelled descriptive comparison; regimes declared (and hashed) before the evaluation, causal ones kept apart from retrospective slices,
  a thin regime reported as insufficient and never as zero; proper scores and reliability, walk-forward Platt and isotonic calibration, rolling split conformal (labelled *without* a coverage guarantee) and adaptive conformal (a long-run average guarantee only).
- **Selection and robustness** (`nested.py`, `sensitivity.py`, `multiseed.py`, `selection.py`): nested chronological selection with an audit that recomputes every window from the label intervals; neighbourhood, delay and capacity decay as child experiments (counted looks, the whole grid reported, a flat distribution noted, an unknown setting refused); multi-seed evaluation over seeds declared first (the median,
  never the best seed; policy variability and time-series uncertainty side by side). A constant candidate is excluded from the selection procedures and the exclusion is recorded.
- **Statistical diagnostics of a saved experiment** (`diagnostics.py`, `analysis_records`, append-only): all of the above on the stored returns, refused on the test or forward segment unless the holdout was evaluated under a frozen plan, stored with the hash of the policy they were computed under. `evaluate_policy` reads the record against the adopted policy and returns one item per required criterion
  (`ok`, `failed`, `missing`, `stale`, `blocked`, `not_applicable`): a correctly implemented losing strategy fails Gate B and still passes Gate A.
- **A prospective ledger** (`prospective.py`, migration 8): commitments are immutable and keyed `strategy version | decision timestamp | universe version | horizon`; the server's clock is the creation time; a commitment is `prospective` only if its data and fit cutoffs are at or before the decision, the model already existed and it was written before the first return of its label could be observed, and is otherwise a `replay`,
  which is stored but never counted. Settlements are appended, a revision with its correction reason, both evaluations kept. `equity` builds daily portfolio equity from the committed holdings through the platform's own execution ledger; it never divides a horizon return by its horizon, and a forecast horizon plays no part in it.
- **Governance** (`governance.py`, migration 9): a strategy-version identity (the model artifact, dataset, model, split, signal, backtest and execution settings, the risk limits and the data hash; the code hash is recorded on every commitment and is not part of the identity), documented risk limits, `commit_forecast` as the one door into the ledger (a limit breach, a halted version or a conflicting commitment is refused and the refusal
  recorded), monitoring (PSI drift, live IC, drawdown, daily loss, staleness), halt, resume and rollback, a written recovery plan, and a human deployment approval tied to the version it approved.
- **Gates** (`gates-v3`, `r5_gates.py`): Gate B reads the statistical diagnostics against the adopted policy and needs the verified procedures (P1-16 to P1-19, and P1-20 to P1-22 when the policy asks for them) and, for reinforcement-learning kinds, a multi-seed record. Gate C reads committed and settled prospective evidence of the *current* strategy version and its operating controls, and needs the machinery (P1-24, P1-25) verified. The selection item
  follows the adopted policy's criteria. Nothing a request carries can set these items. `authorize_stage` for production records its approval through `governance.approve_deployment`.
- **Surfaces**: `GET/POST /api/ml/validation-policy`, `GET /api/ml/statistical-diagnostics` and `POST .../run`, `POST /api/ml/multiseed/run`, `GET /api/ml/governance` with `POST .../governance/version` and `.../action`, and `GET /api/ml/forward` with `POST .../forward/step` (which now commits before it logs, refuses on a limit breach, a halt or a conflict, rejects unknown fields and reports the replay/prospective counts);
  `quant ml-policy`, `ml-diagnostics`, `ml-multiseed`, `ml-governance` and `ml-forward`; the dashboard has a policy card, a diagnostics card, a governance card and, in the forward test, a prospective-ledger card with the equity chart.
- **Verification registry**: 56 requirements (P0-01 to P0-30 and P1-01 to P1-26); the Release 5 test files (`test_ml_statistical_inference.py`, `_matched_benchmarks.py`, `_regime_evaluation.py`, `_calibration_scores.py`, `_nested_selection.py`, `_sensitivity.py`, `_multiseed.py`, `_prospective_commitments.py`, `_forward_equity.py`, `_validation_policy_governance.py`, `_statistical_api.py`, `_statistical_cli.py` and
  `test_webapp_ml_validation_browser.py`) are in the `ml-base`, `replit-python` and browser CI lists; `ml-base` and `ml-correctness` now allow 45 minutes.
- **Not done, said plainly**: P1-15 is `in_progress` (the nested procedure and its audit are verified; the search and tuning flows do not run through it); P1-20 is `in_progress` (signal, backtest and execution settings only, not model hyper-parameter neighbourhoods); P1-22 is `in_progress` (probability calibration is wired into the diagnostics; quantile and interval scores and conformal prediction are library functions that
  the diagnostics do not call); P1-23 is `in_progress` (verified on non-reinforcement-learning families; the agents' multi-seed run was not exercised). No policy has been adopted and no prospective commitment exists outside the tests, so no strategy has a Gate B or Gate C result.

### Release 6 (alpha foundation and portfolio construction)

- **Relative and residual targets** (`targets.py`): `excess_ret_h` (against the equal-weight benchmark) already existed; `sector_ret_h` (the return less its group's mean, needing at least two valid peers; the group map is static and labelled as not point in time) and `resid_ret_h`
  (the return less beta times the benchmark's, with beta the slope of the trailing 252 days, at least 120, ending at the decision date) are added, with a plain-language description in `meta['target_documentation']`. The position rules that need a return forecast refuse a rank or probability output
  (`contracts.check_signal_use`), and a relative target needs a net exposure of zero.
- **Alpha diagnostics** (`alpha.py`): the rank IC per date with its state (`ok`, `too_few`, `tied_signal`, `tied_target`), mean IC with a Newey-West interval (lag at least `h - 1`), a decay grid over extra lags and horizons, coverage, stability across blocks, redundancy
  between features and between signals, a correlation report, the IC conditional on existing signals (`explained_signal` and `explained_target` are distinguished from ties) and the incremental value of a blend.
- **Stable feature selection** (`featsel.py`, model kind `stable_select`): block-subsample stability selection with an IC or a lasso selector, the Meinshausen-Buhlmann bound on expected false selections, per-fold selection frequencies, and a fold with no stable feature is skipped, not filled.
- **Simplicity tie-break** (`parsimony.py`): a one-standard-error rule (paired or independent) and a penalty rule, over a declared complexity (number of features, model family rank, or lexicographic), checked against a frozen plan's `decision_policy.parsimony`; a simulation shows the rule picking the simplest of equal candidates.
- **Controlled comparison harness** (`comparison.py`): the card of spec section 10.2 (hypothesis, study, baseline and candidate versions, the one change, manifests, metrics, selection rule, uncertainty method, multiple-testing scope, budget, minimum coverage, robustness grid, final evaluation policy, `frozen_at`, results,
  negative findings, gate decision, evidence artifacts) frozen in the append-only `analysis_records`; a candidate is the baseline with one declared change merged over it, and anything the family does not allow is refused; arms use identical folds and the same data fingerprint or are `not_comparable`; paired IC
  difference (Newey-West) or paired Sharpe difference (stationary bootstrap) on the validation segment only; Holm over the candidates; verdicts `supported_on_development`, `worse` or `inconclusive`; **the gate decision is always `not_evaluated`**, and a second call returns the stored result and runs nothing.
- **Horizons** (`horizons.py`): a horizon's holding period is the platform's tranche sleeves; the horizon family compares daily net returns and never an h-day return divided by h.
- **Risk models** (`risk_models.py`): sample, EWMA, Ledoit-Wolf constant correlation and identity targets, PCA-denoised and factor covariances fitted as of a date, compared by forecast against realised risk and by weight stability; risk contributions.
- **Cost-aware allocation** (`allocation.py`, signal method `cost_aware_mean_variance`): the objective of spec section 9.2 (return less risk aversion times variance less trading cost less a turnover penalty) with position, gross, net and group limits, participation and impact terms, solver status and residuals, a visible fallback
  (`none`, `hold` or `equal_weight`), a perturbation grid on forecast, covariance, cost and limit, and a simulation with partial fills carried to the next decision. It needs a holding period of 1, solves every `opt_every` sessions, and writes its log to `report['allocation']`.
- **Surfaces**: `GET /api/ml/alpha-diagnostics`, `GET /api/ml/portfolio-diagnostics` (`stored=1` reads the stored record), `GET`/`POST /api/ml/improvement-experiment` (with `from_experiment` and `presets`); `quant ml-alpha`, `ml-portfolio` and `ml-improve`; the dashboard has an alpha card, a portfolio card and an improvement-experiment card. No migration was added.
- **Verification registry**: 67 requirements (P0-01 to P0-30, P1-01 to P1-26 and the eleven below); the Release 6 test files are in the `ml-base` and `replit-python` CI lists and the browser test is in the `browser` list.
- **Not done, said plainly**: P2-16 is `in_progress` (the allocation library makes capital, participation and impact change the feasible trade, but the pipeline method does not pass capital or volume to the optimiser; the realistic mode applies liquidity afterwards, and actual fills are not fed back into the optimiser's holdings); P2-17 is `in_progress`
  (the tie-break applies to comparison cards; the search and tuning flows do not route their winners through it). **No improvement is claimed**: the harness reports a gain only as `supported_on_development`, on development data, and does not touch the protected segments.

### Release 7 (controlled strategy-improvement experiments)

- **Three overlays on the book** (`signals.build_weights`, `OVERLAY_KEYS`): `trade_filter_k`, `no_trade_margin` and `regime_exposure` are optional `signal` settings applied in that fixed order after the position rule. The regime overlay comes last because it is a risk control that only lowers the book (its cap is at most 1). Each leaves a log of what it proposed, made and rejected. None is in the defaults, so no configuration hash changes.
- **No-trade regions** (`notrade.py`, P2-05): the book is moved only if the utility gain (forecast return less risk aversion times variance, from the book actually held) exceeds the incremental cost with a safety margin, and a smaller margin applies while a trading episode is under way (hysteresis). Forced trades (a name that can no longer be held, a position or the gross above its limit) are made whether or not they pay, and are recorded with their reason.
- **Trade filter** (`tradefilter.py`, P2-09): a trade is made only if its net edge in units of the forecast's own root-mean-square error (measured on settled decisions only) is at least `k`. `k` is a setting of a frozen comparison card, compared on the validation segment (each value a counted look), never chosen on a protected segment; the log shows the diversification the filter removes.
- **Calibrated sizing** (`sizing.py`, signal method `calibrated_sizing`, P2-06): the score is calibrated walk-forward (a cross-sectional slope against settled outcomes, with a Newey-West uncertainty). With no demonstrated edge the book is flat; otherwise the bet is shrunk by the uncertainty of the calibration and sized by the asset's risk and the signal's stability.
- **Causal regime exposure** (`regime_exposure.py`, P2-11): filtered states only (smoothed probabilities and calendars chosen with hindsight are refused by name), numbered by volatility at each refit so that a number keeps its meaning, per-state budgets read from the next-day returns of the unscaled book on the rows before the refit, never above 1, and neutral where the evidence is insufficient (`regime_min_train`).
- **Regularised stacked ensemble** (`ensemble_models.stack_weights`, `ensembles.mixture_study`, P2-08): non-negative least-squares weights, normalised and shrunk toward equal weights, optionally per regime, with a member-coverage floor. `mixture_study` compares equal, inverse-volatility and regime-conditioned weighting against the best single member on development data.
- **Meta-label audit** (P2-12): meta-labels are net of the declared cost, carry the producer-fold record of Release 2 and are compared with their base signal through `comparison.compare_saved` (`versus_base`).
- **Delay report** (`delay_report.py`, P2-15): rank IC, expected edge, net result and capacity at delays declared before the numbers are seen (the declaration is hashed), timing in calendar days from the real timestamps, and the stale-book rule: a delayed book is the book decided at the observation close, never a re-read of a newer signal.
- **Comparison families** (`comparison.py`): rebalancing, risk_control, ensemble, execution and combination join target, feature, horizon and portfolio. Parametrised presets, ablation and combination cards with lineage (each parent's p-values stay in the combination's Holm family), `select_baseline` (the best single member on development data, labelled an optimistic baseline) and risk-matched drawdown reporting.
- **Surfaces**: `GET /api/ml/delay-report` (`stored=1` reads the stored record), the extended `POST /api/ml/improvement-experiment`; `quant ml-delay` and the extended `ml-improve`; the delay and improvement cards of the experiment view.
- **Verification registry**: 74 requirements (the 67 above and P2-05, P2-06, P2-08, P2-09, P2-11, P2-12, P2-15); the Release 7 test files are in the `ml-base` and `replit-python` CI lists and the browser test is in the `browser` list.

### Release 8 (optional advanced research and operations)

- **Off by default** (`advanced.py`): twelve modules, none imported by the base workflow (a test starts a fresh interpreter, imports the experiment, search, CLI and API modules and checks that neither the modules nor any optional package is loaded), none scheduled, all running on the base install. `GET /api/ml/advanced` and `quant ml-advanced catalog` list them with their door (API, command line or library), availability and the latest recorded verification.
- **Drift** (`drift.py`, P3-01): PSI and an effective-sample-size KS test of each feature against a reference window fixed at the model's fit cutoff, adjusted across features (Benjamini-Hochberg or Holm), with observation counts and coverage; drift of the settled rank IC only; the link from each look to the last. The PSI levels are heuristics, not significance levels.
- **Retraining proposals** (`retrain.py`, P3-02): triggers with cooldown, a data floor and duplicate suppression; an approval or rejection that names a person; nested validation; suspension after repeated failures and a documented recovery; rollback through governance. A retraining never promotes a challenger and never reads a protected segment. **Starting one is a library call that needs a trainer; the platform supplies none (P3-02 stays `in_progress`).**
- **Uncertainty monitor** (`uncertainty_monitor.py`, P3-11): calibration of the stated interval, drift of the point forecasts, drift of the stated uncertainty and member disagreement, each with its own state; a missing estimate is `unavailable` or `not_applicable` with its reason, never zero; a monitor that could compute nothing is `unavailable`; alerts escalate with persistence. A stored ensemble keeps its members' calibrated forecasts (`ensemble_models` now returns a `members` frame), so disagreement runs on it; a single model has none (`not_applicable`) and an older ensemble is `unavailable`.
- **Champion and challenger** (`champion.py`, P3-10): a pair frozen before the observations (the id is a hash of the declaration), both forecasts committed together under one decision time and data cutoff through the prospective ledger, a predeclared schedule of looks with alpha spending (O'Brien-Fleming, Pocock or equal), and no backfilling. When both ids are governance strategy versions their execution, cost/schedule and risk-limit settings must be identical (a difference is refused); otherwise the assumptions are only declared, and the record says so.
- **Reproducible reports** (`repro_report.py`, P3-12): a report is a pure function of a snapshot (artifact hashes, recorded diagnostics, gates, policy versions) stored with it; it does not change when models or data are updated, `verify_inputs` says what has changed since, and a new build is a new report.

### What running the checks found (and fixed)

- **Findings after Release 8.**
  - *The Python 3.10 job failed a test that passed everywhere else.* The discovery module's look-ahead check compared two evaluations bit for bit. On pandas 2 a frame and its copy are laid out differently in memory, so a row-wise mean adds its terms in another order and the last bit differs (about 2e-16), and a valid expression was reported as looking ahead. It was a defect of the check, not of the expression: it now requires agreement to within 1e-9 (far below any dependence on the scrambled future, whose noise has scale 10) and reports the tolerance, and a test shows that a rounding difference passes while a value that reads the next row, and a cell that goes missing because of the future, do not.
  - *The evidence environment did not cover that lane.* Every earlier evidence run used a pandas 3 copy of the Python 3.11 CI environment, so a difference that exists only on Python 3.10 with pandas 2 could not show up. The evidence now also runs the whole file list of the `replit-python` job in a copy of that lane (Python 3.10, pandas 2.3.3, with PyTorch, NGBoost, Optuna, Gymnasium and Stable-Baselines3).
  - *A CatBoost fit wrote a `catboost_info` folder into whatever directory the application was started in*, found because the serialization matrix now fits every kind; the estimator is now told to write nothing, and a test runs a fit in an empty directory.
  - *A classifier's second probability column was taken to be class one without looking at the classes*; the classes and the bounds are now checked where the probabilities are produced.
  - *The dashboard did not show the probability scores at all* (only a note when there were none), although the diagnostics record held them; it now shows them.
- **Release 8 findings.**
  - *The response envelope reserves `as_of`*, and the drift and monitor payloads carried their own; the first API test failed on it, and the date now moves into the envelope's field.
  - *An off-policy test meant to show a collapsed effective sample used a behaviour policy that agreed with the target*, so its weights were mild and the estimate was (correctly) given; the log now prefers the action the target does not take.
  - *A panel stacked into one series hid its serial dependence from the effective sample size*; the drift test computes it per asset and averages.
  - *The discovery grammar accepted `lag(x, -1)`*, which reads the future; a negative window is refused with its reason, and a generated-expression property test checks that nothing the grammar accepts changes its past values when the future is scrambled.
  - *Wiring the surfaces exposed three gaps that were not visible in the library tests.* Two were closed in the same release: a pair's shared assumptions are now compared with the two versions' recorded settings (P3-10), and an ensemble now keeps its members' forecasts so the disagreement check runs on stored experiments (P3-11), with an older ensemble reported `unavailable` rather than as a single model. The third stays `in_progress`: no trainer exists for `retrain.start` (P3-02), and what a retraining means here is a product decision.
  - *Commitments made through the API are stamped with the real clock*, so the champion tests use decision dates years ahead and cutoffs in the past; the library tests inject the time.
  - *Evidence procedure*: the evidence run was produced in an isolated clone of the final tree and is resumable; the worker restarted several times while it was written and nothing was lost.
- **Release 7 findings.**
  - *A paired comparison of an experiment with itself* returned a value where the difference is constant zero; it is `insufficient` (no estimate), and the test now expects that.
  - *A comparison card listed derived settings* (`cost_bps` and the like) among the changes a candidate made, which made one change look like several; derived keys are filtered from `changed` and shown under `derived`.
  - *The regime overlay never acted in development mode*: the book exists only on the validation part of the timeline, so a fit on the rows before it had too few rows. `regime_min_train` (default 252) is now a setting, the tests use smaller values, and the overlay stays neutral, visibly, where the evidence is insufficient.
  - *The delay-report fixtures disagreed with the engine's fill convention* (a decision at `t` earns the return of `t + lag + extra + 1`; the executed book is the one decided `lag + extra` sessions earlier); the fixtures were rebuilt on that convention rather than the report changed.
  - *The mean IC of a constant IC series came back as `None`*; a plain `mean_ic` is reported next to the inferential value.
  - *Two ablation candidates from different cards could share a name*; the family and a fragment of the card id are part of the name.
  - *Preset validation errors* are raised when the request is made (an `ApiError`), not later as a job error; the test and the documentation say so.
  - *Stacked ensemble weights* are constant within a fold, not across folds; the test asserts the first, and an empty-slice `RuntimeWarning` is suppressed where an empty slice is the answer.
- **Release 6 findings.**
  - *A cross-sectional demeaning raised a shape error on pandas 3* (`DataFrame.where` with a one-dimensional condition against a two-dimensional frame); the group-relative target now masks with `axis=0`.
  - *The stable-selection test failed because the perturbation changed the labelled axis*: filling the unlabelled tail lengthened the labelled panel and moved the fold boundaries; the test keeps the missing labels missing, and the selection is checked on the same boundaries.
  - *The first comparison harness gave every candidate as a standalone configuration*, so every default the baseline set looked like a difference; a candidate is now the baseline with one declared change merged over it, and a candidate that is the baseline is refused.
  - *A constant paired difference produced a standard error of zero*: it is `insufficient` (no estimate), not an effect of zero or an infinite t.
  - *The shared response envelope reserves the key `notes`*; the portfolio card's caveats were renamed rather than the envelope changed.
  - *The portfolio diagnostics took the segment from the plan instead of from the experiment's own returns*, which disagreed by a few days; they use the dates on which the saved book earned.
  - *Alpha-diagnostic fixtures*: the participation ratio of a block with 16 and 6 effective observations is 16/6, not 3, and a conditional-IC fixture needs more dates than the number of conditioning signals plus four; both were mistakes in my first expectations, and the conditional IC now distinguishes `explained_signal` and `explained_target` from a tie.
  - *Evidence procedure*: the evidence runs were produced in an isolated clone of the final tree and are resumable (a marker per stage), because a restart of the worker killed the first attempt.
- **Release 5 findings** (each found by a test or an evidence run, none by inspection alone).
  - *A conflicting commitment lost its audit row*: the rejection was raised inside the transaction that wrote the audit, so the rollback took the audit with it. The audit is committed first and the error raised after (a first repair inserted the commitment in the conflict branch too; the same test caught that).
  - *A bootstrap interval of `[None, None]` was reported as `applied`* for exactly 100 replications. A percentile interval from fewer than 200 replications is now `insufficient` and a missing bound reads as `missing` in the policy.
  - *A constant candidate produced `applied` deflated-Sharpe, FDR and PBO results with NaN statistics and an opaque SPA failure.* It is now excluded from the selection procedures, the exclusion is recorded in the scope and limitations, and a direct call returns `unsupported`.
  - *The neighbourhood analysis accepted a setting that does not exist* (`signal.top_frac`) and reported a flat distribution as robustness. Unknown settings are refused and a distribution in which every point is identical is noted.
  - *Diagnostics could be computed on the sealed test and forward segments.* They are refused unless the holdout status is `evaluated_under_plan`.
  - *A forward-test conflict still wrote a signal*: the conflict path and the refused path now log none, and the result says so.
  - *A policy error escaped the API's error handling* (policy construction sat outside the guard) and surfaced as a server error.
  - Several first versions of the new tests encoded wrong expectations of mine (skewness fixture magnitudes, an index alignment in the equity fixture, a trigger test that needs a row to exist first, the job-status path of an API error); each was corrected in the test after checking the code against an independent calculation.
  - *Evidence procedure*: the three evidence runs (verification, regression, browser) were produced in an isolated clone of the final tree, as for Release 4, so that editing files meanwhile cannot make the provenance item stale.

- **Release 4 findings.**
  - *Run 105, `browser` job*: `test_tuning_one_model...` expects a verdict card, and a tuning that does not evaluate the protected segments (the default since Release 3) produced none. The tuning summary now has a validation-only verdict that says what it did and did not look at.
  - *Run 105, `docker` job*: the image has no `.github` directory, so `tests/test_ml_ci_policy.py` (which reads the workflow) failed at collection. It is skipped at module level when the directory is absent; the lane that has the workflow still runs it.
  - *Regression group*: `tests/test_ml_data.py::test_the_yaml_defaults_load_and_agree_with_the_python_defaults` iterated the configuration sections and failed on the new optional `execution` section, which is deliberately absent from the defaults (its absence is the legacy mode). The test now says so and asserts it.
  - *A procedure finding, not a code defect*: my first regression run used the default `-n 3` distribution, which splits a module's tests across workers; `test_ml_research_api.py` has a test that depends on state built by an earlier test of the same module and failed. CI uses `--dist loadfile`, and so does the run above.
  - *Evidence must come from an unchanging tree*: during one `ml-verify` run, two `test_ml_promotion_gates.py` tests failed because I was creating files under `src/` meanwhile. That is the provenance item working as designed (it compares the experiment's recorded source-tree hash with the checked-out code, so editing source
    while a test runs makes Gate A stale). The evidence above was therefore produced in an isolated clone of the final tree, and the same two tests pass there.
  - Implementation faults found by the new tests along the way (fixed): a read-only array under pandas 3 in the liquidity screen; an order resized the wrong way when delay exceeded one session; a short that was being exited was rejected as a new buy; the capacity curve used a flat last target instead of the last decision.
- **pandas 3 datetime units.** `DatetimeIndex.asi8` counts in the index's own unit, and pandas 3 picks that unit by what it parsed (microseconds here). The session and point-in-time code treated the integers as nanoseconds, so a bar's age came out 1,000
  times too small and the availability join saw nothing public. CI found it (the seven failures above); my first local runs used pandas 2.3.3 and missed it, and the brute-force oracle I had written for the join shared the same flaw and passed vacuously.
  Now every comparison goes through one nanosecond conversion (`sessions.ns`), the oracle is independent of it, and every local gate runs on a pandas 3.1 copy of the CI environment.
- **A defect in the regime model's diagnostics**, found by the training-isolation test: the regime statistics it reported as "training" included the block it was then asked to predict. They now stop at the fit window.
- **Strategy combination by online learning** back-filled the first volatility from later days and filled gaps from the whole sample (found by the fill audit). It now makes no update until 20 days of trailing volatility exist; results of earlier runs are not re-evaluated.
- **`idio_vol_63` declared a 63-day lookback and needs 126** (found by the dependency audit).
- **Saved reports carried too few fold fields**: the first regression run failed on `KeyError: 'fit_cutoff'` when meta-labelling a run saved without lineage. Runs saved before this release now say `not recorded`.
- **A feature dtype check that numpy cannot make**: pandas 3's text dtype has no numpy equivalent, so the first version of the model's dtype safety net skipped it. It reads the dtype kind from pandas.

## Compatibility and migration

- Existing experiments, registry rows and model files are untouched. Experiments saved before this release have no fold lineage, no dataset audit and no inference bundle, and say `not recorded`; they still load, re-backtest and track forward.
- `split.sample_weighting` and `dataset.sessions` are absent from the defaults, so no existing configuration hash changes; setting either makes a different experiment.
- Training rows are chosen by label interval. On a calendar without missing dates this selects exactly the rows the old position rule did (tested); where dates are missing it keeps rows the old rule dropped and still leaks nothing.
- A panel built for another target, horizon, lag, scaling or feature set than the configuration asks for is refused instead of trained on.
- For a universe whose assets close at different times (a crypto day against a US close), the default is now to read the later-closing assets as of the decision; `dataset.sessions.policy: date_labels` reproduces the earlier join.
- Strategy combination by online learning no longer back-fills (see above); `params.volatility_fill` records `causal_v2`.
- Release 3 adds migrations 2 to 6 (lineage, provenance, holdout, selection evidence and null studies, gate decisions). They only add tables and triggers; a registry written before them opens in place, keeps every row (tested), applies nothing twice, and a migration that fails halfway leaves
  no trace. Experiments saved earlier have no lineage, provenance or holdout record and say `not recorded`; the lineage of a study that holds only such experiments shows zero looks (none is invented), and `trial_count` is unchanged for them.
- **Defaults that changed** (documented in the limitations note): `finalize` is off in the API, the search and the CLI (the old behaviour is `finalize=true`, which now freezes a plan and consumes it with a deprecation text); `optimization.finalize` and `explainability.feature_ic` raise when a
  registry is in use and no horizon or evaluation context is given; `Registry.promote` blocks staging and production without gate evidence (taking a model out of production needs none); `POST /api/ml/train` defaults to `mode: full`, which records a holdout *exposure*, not to `development` — a deliberate
  deviation from "development by default", so that existing callers keep their results, with the exposure visible in the report.
- Release 4 adds no migration. `execution` is optional and absent from the defaults, so no configuration hash changes; an experiment saved earlier is read as `vectorized_legacy` and the report says `recorded: false`. A realistic re-run has a new id and a recorded parent; `rebacktest` accepts an `execution`
  section (and refuses a lag setting), and a tuning that does not evaluate the protected segments returns a validation-only verdict instead of none.
- Release 5 adds migrations 7 to 9 (analysis records, validation policies and adoptions; commitments, their audit and settlements; strategy versions, risk limits and governance events), all additive with append-only or immutable triggers; a registry written before them opens in place and keeps every row (tested). The gate policy is `gates-v3`, so earlier gate decisions read as stale.
- The commit after Release 8 adds no migration. `GET /api/ml/catalog` has one more key (`architectures`) and the diagnostics record one more section (`interval_calibration`); the classifiers' `predict_proba` can now raise `OutputContractError`; `discovery.causal_check` reports its `tolerance`.
- Release 8 adds no migration and no configuration setting; the new record kinds (`drift_report`, `retrain_event`, `champion_challenger`, `uncertainty_monitor`, `reproducible_report`) are `analysis_records`. `allocation.solve` accepts a per-name `holding_penalty`; without it the problem is unchanged. Nothing in the base workflow imports the new modules (tested).
- Release 7 adds no migration. `signal.no_trade_margin`, `no_trade_hold_margin`, `trade_filter_k` (with `trade_filter_cost_margin` and `trade_filter_window`) and `regime_exposure` (with `regime_states`, `regime_floor`, `regime_cap`, `regime_min_train` and `regime_min_days`) are absent from the defaults, so no existing configuration hash changes; `calibrated_sizing` and the `stacked` and `stacked_regime` weightings of `model_ensemble` are new, additive choices. Delay reports, mixture studies and the new comparison families are `analysis_records` of new kinds.
- Release 6 adds no migration. `signal.holding_period` accepts the horizons 1, 5, 10 and 20; `cost_aware_mean_variance` and `stable_select` are new, additive kinds; `signal.cost_bps`, `window_days`, `label_offset`, `rebalance` and `lag_total` are derived by the configuration only when a Release 6 rule needs them and are absent otherwise, so no existing configuration hash changes. Comparison cards, results and diagnostics are `analysis_records` of new kinds.
- **Behaviour that changed**: the forward-test summary no longer returns `cumulative`, `sharpe` or `series` (they compounded a horizon return divided by its horizon, which is not a daily P&L); it returns `horizon_outcomes` and, with `monitor=True`, the monitoring result. `POST /api/ml/forward/step` rejects unknown fields. The selection item of the gates follows the adopted policy's criteria when there is one and the earlier defaults when there is not. Nothing is
  re-evaluated: experiments and forward signals saved earlier keep their stored numbers, and a forward test without commitments says so.
- Release 1's items (RL state schema 2, output contracts, the `QFM1` envelope, the registry migrations) are as described in the Release 1 section of the architecture note.

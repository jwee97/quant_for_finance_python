# Running on Replit

This import keeps the original Python project structure and Quant Lab dashboard.

## Workspace preview

Use **Run** to start the **Quant Lab** workflow:

```sh
python -u -m src serve --host 0.0.0.0 --port 5000 --no-browser
```

Open the Preview to use the backtest, comparison, strategy builder, execution and cash-flow labs, and guides.
The server permits Replit preview embedding only when bound to a non-loopback
address in a Replit development environment. API calls still require the
per-launch token generated by the existing server.

**Access warning:** this is a research dashboard, not a multi-user hosted
service. Anyone who can open its page can submit backtests and modify the shared
research session. Do not publish it or expose it to untrusted users without
adding authentication and resource limits.

## After you pull an update

The app loads its Python code when it starts and keeps running after you pull new
files, so **press Stop and then Run again after every update** (the page itself is
read from disk each time, so it can be newer than the app behind it). If you forget,
the page says so instead of failing: a red banner reading *The app is older than
this page* means the app must be restarted, and a banner reading *The app was
updated after it started* means some of its code changed on disk since it started.
The Execution and Cash flows tabs need a newer app than the Backtest tab does, so with an
older one the Backtest keeps working and those two tabs say that they need a restart; the
Options, Futures and Crypto tabs, and the Free data cards on them, need newer ones still, and
the Tune tab, the Forecast tab and the Machine learning tab the newest, and say so in the same way.
Your saved tickers and runs are kept across restarts.

## Free data for the Options, Futures and Crypto tabs

Each of those three tabs has a **Real data (free)** card in its left panel: tick tickers,
futures roots or coins and press **Download real data**. The app fetches real option
chains (Cboe, Deribit), futures curves of 44 roots (Yahoo Finance, Deribit) and crypto
prices, order books and funding (OKX, Coinbase, Kraken, Bitstamp, Deribit), saves them
under `data/user/downloads/` and the tab switches to them, badged *Downloaded: free data*.
Those sources need no account, no key and no Secret, and nothing has to be sourced by hand.

**Finding a future without guessing its symbol.** The Futures card's *Yahoo: search any future*
source searches every future Yahoo Finance lists (about 340 in the list that ships with the
app, and *Ask Yahoo for what you typed* finds the rest by name) and downloads its daily price
history, no key needed, to read in the History view. Yahoo has CME Group and ICE US futures
only; iTick's list below has Hong Kong and mainland China as well.

**iTick** is the optional second source of the Futures and Crypto cards (choose it above
the list of roots or coins) and of the Options card's price download. It uses the same
`ITICK_API_KEY` Secret as the Backtest tab's iTick source (see below), the same 5-calls-a-
minute limit and the same cost per download, and it gives you the daily price history of
**any** of about 1,600 futures products (search the list in the card; you are not limited
to the 44 roots), a coin's daily history, and an option underlying's daily prices. It has
no option data and no curve (iTick keeps one series per futures product, not one per
contract month). A card with iTick chosen and no key set shows the steps that turn it on.
The author could not call iTick with a working key, so press **Test the iTick connection** in
the card once the Secret is set: it spends one call (two if the first iTick host does not
recognise the key) and says what your account returns. If a product is "not found", iTick
says its code is wrong or it is not in your plan; the test then also tries NQ, iTick's own
example, to tell a plan without futures from one missing product, and the search marks what
your key could and could not get.

The public feeds rate-limit shared cloud addresses, and a Repl's address is shared. If a
provider answers *HTTP 403* or *HTTP 429* the card says which one and the app waits before
asking that host again: try again in a few minutes, download fewer items at a time (Yahoo
is the strictest), or run the dashboard on your own computer. What is downloaded, how it is
read and what it is not (delayed, unaudited, no open interest from Yahoo): [docs/free_data.md](docs/free_data.md).

## Training in the background on Replit

**What the app does.** A training, a search or a re-backtest runs on the app's own worker
thread, not in the browser: closing the tab or reloading the page does not stop it, and the
experiment is saved to the registry when it ends. Because a reloaded page used to forget what
it had started, the app keeps a small record of every job in `data/user/jobs/`, and the
Machine learning tab shows a card, *Runs in the background*, with what is running, waiting
or ended in the last six hours: it follows them, opens the experiment a finished run made, and
shows a run that was lost as *Stopped* (within about a minute of a crash), with the last thing it was doing. *Clear* takes a row off the list, and *Not running? Clear* takes off a run that still says running after a crash. Nothing is
checkpointed or resumed: a lost run starts again from the beginning. Runs go one at a time, so
a long search delays anything queued behind it. The Tune tab's searches ([docs/tuning.md](docs/tuning.md)) and the
Machine learning tab's tuning are jobs of the same kind, with a *Stop* button on the row: a Kalman trend search on
the 15 ETFs takes about a second a try (Quick: half a minute), a model that is fitted every month takes much longer. The Forecast tab ([docs/forecasting.md](docs/forecasting.md)) is a job of the same kind: with every method, Quick takes about half a minute on a laptop, Standard a minute and a half, Thorough four minutes, and a Replit workspace is slower.

**What Replit does.** This is from Replit's documentation as of October 2026; it could not
be tried from here. The workspace's preview address is described as temporary and live only
while you actively work on the app, so once you leave, Replit can stop the Repl, and with it
the training. No grace period is documented, and the app cannot prevent it: it can only tell
you afterwards that the run was lost. What that means in practice:

- **Short runs are fine if you stay.** Timed on a 4-core machine with nothing else running,
  `python -m src ml-train --universe etf --rebalance weekly` trained a ridge model on the
  15 ETFs in about 30 seconds and a boosted-tree model (`--model hist_gb`) in about two
  minutes, each peaking near 440 MB of memory. The same boosted-tree run took seven minutes
  when other work was using the machine at the same time, so expect more on a smaller Repl,
  and more while a backtest or a download runs in it. Keep the Replit tab open and the
  device awake until the card says *Finished*. A search of a dozen trials or more takes much
  longer: do not count on leaving Replit for it.
- **Run it from the Shell, and read the answer in the log.** The same pipeline is a command:
  `python -m src ml-train --model hist_gb --universe etf --rebalance weekly --name nightly`.
  `nohup python -m src ml-train ... > train.log 2>&1 &` runs it detached from the Shell, and
  `tail -f train.log` follows it; the experiment goes to the same registry, so it appears in
  the Experiments list. It still stops if the Repl does.
- **A run you want to leave alone: a Scheduled deployment.** Publish the command above (not
  the dashboard) as a *Scheduled* deployment: Replit runs it on a schedule, on its own machine
  (1 vCPU and 2 GiB when it was announced), for up to 11 hours, and bills compute per second
  while it runs. The run's printed summary (Sharpe by segment, rank IC, the warnings) is in the
  deployment's logs. The file system of a published app is *not persistent and resets every
  time you publish* (Replit's own words), so the saved experiment does not come back to your
  workspace: treat the log as the result, or copy what you need out. (Replit's
  troubleshooting page says a published program that runs once and exits is restarted
  automatically, so a one-off command belongs in a Scheduled deployment, not in a Reserved VM
  or an Autoscale one.)
- **Do not publish the dashboard to keep it awake.** A Reserved VM never sleeps, and would keep
  the app and its runs alive, but a published address is open to anyone who has it, and this
  dashboard has no login (see the access warning at the top): strangers could spend your iTick
  calls and your machine. Add authentication first, or use your own computer or server, where a
  process lives as long as the machine does.

## If the Machine learning tab says LightGBM or XGBoost is not available

Both are optional and need the operating system's OpenMP runtime (`libgomp.so.1`), which a
Repl may not provide. The tab lists them as not available, with the reason, and every other
model works; scikit-learn's histogram gradient boosting is the same kind of model and needs
nothing extra. See [docs/ml_platform.md](docs/ml_platform.md) for how to switch them on.

## Locking the page with an access code

A Replit preview address can be opened by anyone who has the link, and the page hands its per-launch token to whoever loads it, so the token alone does not keep a stranger out of your backtests, your
background runs or your iTick allowance. To ask for a code first, add a Secret named `QUANT_LAB_ACCESS_CODE` (Tools > Secrets) with a code you choose, then **Stop** and **Run**. The page, its scripts and
the API are then served only to a browser that has typed the code into a small form. The browser keeps a cookie (HttpOnly, SameSite=Strict, and Secure behind Replit's HTTPS) that the app forgets when it
restarts; ten wrong guesses in five minutes close the form for five minutes; `/logout` signs a browser out. Without the secret nothing changes. The code is compared in constant time and is never written to
a log, a file or a page.

## Dependencies and command-line use

Python 3.10 is configured. Project dependencies are declared in
`pyproject.toml`; `requirements.txt` additionally includes deep-learning,
boosting, and testing dependencies. Install project packages through Replit's
package tools. No Docker or virtual environment is needed. Run installs `timesfm` if it is missing (the
`timesfm` model needs it, and PyTorch); if the model still reports an import error, the error names the
missing package and the exact `pip` command for the interpreter the app runs on.

Run commands from the repository root so they use the working-tree source:

```sh
python -m src demo
python -m src list models
python -m src explain "deflated sharpe"
python -m pytest tests/test_webapp.py
```

The demo and default universe use the imported cached market data. New ticker
requests use the data source chosen in the dashboard: Yahoo Finance (the default;
it needs network access and is subject to provider availability/rate limits) or
iTick (it needs an API key; see below). Core dashboard use needs no API keys.
Optional Anthropic assistant features need their separate dependency and
`ANTHROPIC_API_KEY`; they are not configured as part of this setup.

## Using iTick: keeping the API key safe

1. In the Replit workspace open **Tools**, then **Secrets** (under *Setup*), choose
   **New Secret**, enter the key `ITICK_API_KEY` and your iTick API key as the
   value, and **Add Secret**. Stop the app and press **Run** again so it starts
   with the secret. Replit encrypts secrets and passes them to the app as
   environment variables.
2. In the dashboard choose **iTick** under *Download other tickers from* and press
   **Test the iTick connection** (or run `python -m src itick-test` in the Shell): it
   spends one call (two if the first iTick host does not recognise the key) and shows
   which host answered and whether the key, the plan and the daily interval work.

Rules for the key:

- It lives only in Secrets. Never paste it into a chat, an issue, a commit or a
  file. In particular do not put it in `.replit` (its `[env]` section is committed
  to the repository), `replit.nix` or `config/*.yaml`.
- The server reads it from the environment, sends it to iTick in one request
  header over HTTPS, and never puts it in a page, a response, a log line, an error
  message or a cache file. The page only learns whether a key exists.
- Anyone you add to the Repl as a collaborator can see secret values. A Repl that
  is not published is still reachable by anyone who has its link: they cannot see
  the key, but they can use the dashboard and so spend your iTick calls. Do not
  share the link.
- If a key leaks, create a new one in your iTick account and replace the secret.
- If iTick says the key is not valid: paste the key again with no quotes or spaces, then
  Stop and Run (a secret is read when the app starts). The app sends it to
  `api-free.itick.org`, iTick's free-trial host, and asks `api.itick.org`, its production
  host, once if the first does not know it; the test button says which one answered. An HTTP
  403 means the key is known but your plan does not include that data (futures, for
  example). [docs/dashboard.md](docs/dashboard.md#if-itick-rejects-the-key) has the details.

The free plan allows 5 calls a minute. The app enforces that for every iTick call
(a download waits and the progress line says so), remembers recent calls across
restarts in `data/user/itick_calls.json`, caches downloads for a day and tops them
up with one call per ticker. See [docs/dashboard.md](docs/dashboard.md) for the
settings (`ITICK_CALLS_PER_MINUTE`, `ITICK_BASE_URL`, `ITICK_DAILY_KTYPE`, ...) and
for what is and is not verified about iTick's data.

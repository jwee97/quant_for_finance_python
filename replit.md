# Running on Replit

This import keeps the original Python project structure and Quant Lab dashboard.

## Workspace preview

Use **Run** to start the **Quant Lab** workflow:

```sh
python -u -m src serve --host 0.0.0.0 --port 5000 --no-browser
```

Open the Preview to use the backtest, comparison, strategy builder, execution and cash-flow labs, and guides.
The server permits Replit preview embedding only when bound to a non-loopback
address in a Replit development environment. API calls still require the
per-launch token generated by the existing server.

**Access warning:** this is a research dashboard, not a multi-user hosted
service. Anyone who can open its page can submit backtests and modify the shared
research session. Do not publish it or expose it to untrusted users without
adding authentication and resource limits.

## After you pull an update

The app loads its Python code when it starts and keeps running after you pull new
files, so **press Stop and then Run again after every update** (the page itself is
read from disk each time, so it can be newer than the app behind it). If you forget,
the page says so instead of failing: a red banner reading *The app is older than
this page* means the app must be restarted, and a banner reading *The app was
updated after it started* means some of its code changed on disk since it started.
The Execution and Cash flows tabs need a newer app than the Backtest tab does, so with an
older one the Backtest keeps working and those two tabs say that they need a restart; the
Options, Futures, Crypto and Machine learning tabs, and the Free data cards on the first
three, need newer ones still, and say so in the same way.
Your saved tickers and runs are kept across restarts.

## Free data for the Options, Futures and Crypto tabs

Each of those three tabs has a **Real data (free)** card in its left panel: tick tickers,
futures roots or coins and press **Download real data**. The app fetches real option
chains (Cboe, Deribit), futures curves (Yahoo Finance, Deribit) and crypto prices, order
books and funding (OKX, Coinbase, Kraken, Bitstamp, Deribit), saves them under
`data/user/downloads/` and the tab switches to them, badged *Downloaded: free data*. No
account, no key and no Secret are needed, and nothing has to be sourced by hand.

These are public feeds that rate-limit shared cloud addresses, and a Repl's address is
shared. If a provider answers *HTTP 403* or *HTTP 429* the card says which one and the app
waits before asking that host again: try again in a few minutes, download fewer items at a
time (Yahoo is the strictest), or run the dashboard on your own computer. What is
downloaded, how it is read and what it is not (delayed, unaudited, no open interest from
Yahoo): [docs/free_data.md](docs/free_data.md).

## If the Machine learning tab says LightGBM or XGBoost is not available

Both are optional and need the operating system's OpenMP runtime (`libgomp.so.1`), which a
Repl may not provide. The tab lists them as not available, with the reason, and every other
model works; scikit-learn's histogram gradient boosting is the same kind of model and needs
nothing extra. See [docs/ml_platform.md](docs/ml_platform.md) for how to switch them on.

## Dependencies and command-line use

Python 3.10 is configured. Project dependencies are declared in
`pyproject.toml`; `requirements.txt` additionally includes deep-learning,
boosting, and testing dependencies. Install project packages through Replit's
package tools. No Docker or virtual environment is needed.

Run commands from the repository root so they use the working-tree source:

```sh
python -m src demo
python -m src list models
python -m src explain "deflated sharpe"
python -m pytest tests/test_webapp.py
```

The demo and default universe use the imported cached market data. New ticker
requests use the data source chosen in the dashboard: Yahoo Finance (the default;
it needs network access and is subject to provider availability/rate limits) or
iTick (it needs an API key; see below). Core dashboard use needs no API keys.
Optional Anthropic assistant features need their separate dependency and
`ANTHROPIC_API_KEY`; they are not configured as part of this setup.

## Using iTick: keeping the API key safe

1. In the Replit workspace open **Tools**, then **Secrets** (under *Setup*), choose
   **New Secret**, enter the key `ITICK_API_KEY` and your iTick API key as the
   value, and **Add Secret**. Stop the app and press **Run** again so it starts
   with the secret. Replit encrypts secrets and passes them to the app as
   environment variables.
2. In the dashboard choose **iTick** under *Download other tickers from* and press
   **Test the iTick connection** (or run `python -m src itick-test` in the Shell): it
   spends one call and shows whether the key, the host and the daily interval work.

Rules for the key:

- It lives only in Secrets. Never paste it into a chat, an issue, a commit or a
  file. In particular do not put it in `.replit` (its `[env]` section is committed
  to the repository), `replit.nix` or `config/*.yaml`.
- The server reads it from the environment, sends it to iTick in one request
  header over HTTPS, and never puts it in a page, a response, a log line, an error
  message or a cache file. The page only learns whether a key exists.
- Anyone you add to the Repl as a collaborator can see secret values. A Repl that
  is not published is still reachable by anyone who has its link: they cannot see
  the key, but they can use the dashboard and so spend your iTick calls. Do not
  share the link.
- If a key leaks, create a new one in your iTick account and replace the secret.

The free plan allows 5 calls a minute. The app enforces that for every iTick call
(a download waits and the progress line says so), remembers recent calls across
restarts in `data/user/itick_calls.json`, caches downloads for a day and tops them
up with one call per ticker. See [docs/dashboard.md](docs/dashboard.md) for the
settings (`ITICK_CALLS_PER_MINUTE`, `ITICK_BASE_URL`, `ITICK_DAILY_KTYPE`, ...) and
for what is and is not verified about iTick's data.
